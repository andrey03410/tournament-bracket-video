# OST Top Builder — генератор видео

Веб-приложение — генератор шаблонных видео. Три режима:

1. **Топ через турнир** — попарные сравнения треков (аудио и/или видео)
   строят рейтинг, из него рендерится видео-«топ».
2. **Ручной топ** — тот же формат, но позиции собираются вручную из пула
   медиа (аудио или видео со звуком), без турнира.
3. **Пикер** («выбери персонажа / OST / опенинг») — раунды с правилом сверху
   и 2–9 блоками: блоки появляются по одному с анимацией (видео-блок играет
   свой звук, фоновая музыка приглушается), в конце все раскрываются под
   интерактивный таймер с кольцом, опционально подсвечивается «ответ».

Доступ разграничен ролями: гость видит только приветственный экран,
пользователь работает в лимитах, админ может всё; личный кабинет управляет
файлами на сервере.

Спецификации и план — в [`.ai/`](.ai/). Видение: [`.ai/specs/00-vision.md`](.ai/specs/00-vision.md).

## Стек

- **Next.js 14** (App Router, React 18) — фронт + API.
- **Prisma + SQLite** (MVP; продакшн-таргет Postgres — смена `provider` в схеме).
- **Auth.js (next-auth v5)** — email + пароль.
- **Remotion** — рендер видео (16:9, 1080p).
- **ffmpeg-static** — декод/нарезка аудио, RMS-анализ активного сниппета.
- **Vitest** — тесты.

## Требования

Перед запуском должны быть установлены:

| Что                         | Зачем                                   | Как проверить            |
|-----------------------------|------------------------------------------|--------------------------|
| **Node.js ≥ 18.17** (лучше 20 LTS) | Next.js 14 и весь бэкенд          | `node -v`                |
| **npm** (идёт с Node)       | установка зависимостей                   | `npm -v`                 |
| **Google Chrome / Chromium** | только для **рендера MP4** (Remotion)   | `google-chrome --version` |

Ставить отдельно **не нужно**: ffmpeg (идёт в комплекте — пакет
`ffmpeg-static`), SQLite (встроен в Prisma), Remotion/React/Prisma и прочее —
всё приходит через `npm install`.

## Быстрый старт

```bash
npm install
cp .env.example .env          # отредактируйте AUTH_SECRET и ADMIN_EMAILS
npx prisma generate
npx prisma db push            # создаёт SQLite-схему (prisma/dev.db)
npm run dev                   # http://localhost:3000
```

`ADMIN_EMAILS` — email-ы (через запятую), которые автоматически получают роль
администратора при входе/регистрации.

### Браузер для рендера (важно)

Рендер MP4 выполняется Remotion-ом в headless-браузере. Какой браузер
использовать, задаёт переменная **`REMOTION_BROWSER_EXECUTABLE`** в `.env`:

- Укажите путь к установленному Chrome/Chromium — например,
  `/usr/bin/google-chrome` (Linux), `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` (macOS).
- Если переменная **не задана**, Remotion попытается **скачать из интернета**
  свой chrome-headless-shell; в окружении без сети рендер упадёт с ошибкой
  вида «could not download / no browser executable». Скачивание можно сделать
  заранее: `npx remotion browser ensure`.
- Всё остальное (сравнения, конструкторы, живое превью) работает **без**
  браузера — он нужен только кнопке «🎬 Рендерить видео».

## Роли

| Роль    | Возможности                                                                 |
|---------|------------------------------------------------------------------------------|
| Гость   | Только приветственный экран (описание возможностей + вход/регистрация)       |
| Пользователь | Топы и конструктор с живым превью; лимиты: 1 архив ≤100 МБ, пул медиа ≤100 МБ; рендер недоступен |
| Админ   | Всё без лимитов (архив до 10 ГБ) + админка: роли и удаление пользователей     |

Роль читается из БД на каждый запрос — смена роли действует сразу, без
перелогина. Проверки в коде идут по пермишенам через матрицу
`src/lib/domain/permissions.ts`; новая роль добавляется одной записью в неё.
**Личный кабинет** (`/account`): профиль, квоты «занято X из Y», менеджер
архивов/пула/рендеров с размерами — удаление стирает файлы с сервера.

## Поток использования

1. Регистрация / вход.
2. **Создать топ**: название, схема (сравнительная сортировка / швейцарка / круговая),
   слепой режим (опц.), ZIP-архив с треками — аудио (mp3/m4a/flac/…) и/или видео
   (mp4/webm/mov, рекомендуется MP4 H.264+AAC), лимит 10 ГБ (админ) / 100 МБ
   (пользователь). Инструкция «Как подготовить архив» — прямо на форме.
3. **Сравнения 1-на-1**: прослушать/просмотреть A/B, выбрать лево / ничья / право.
   Видео-треки играют в видеоплеере; в слепом режиме скрываются и названия, и
   видеоряд (трек играет как аудио до «Показать названия»). Прогресс сохраняется.
4. **Итоговый топ**: выбрать размер top-N.
5. **Конструктор рендера**: единый пул медиа (картинки + видео; массовая загрузка
   drag&drop, поиск, фильтр по типу, «недавние», постеры для видео). На каждую
   позицию — визуал (картинка, видео из пула или собственный видеоряд видео-трека)
   с недеструктивной обрезкой 16:9; звук — от трека или от вставленного видео
   (полная подмена OST видеорядом); сдвиг старта видеоряда, короткое видео
   зацикливается. Фрагмент — ручной таймлайн или активный сниппет; живой
   предпросмотр.
6. **Рендер** → скачать видео.

**Импорт по ссылке**: в менеджере медиа можно вставить ссылку на видеоролик
(YouTube и другие сайты, поддерживаемые yt-dlp) — сервер скачает его **фоново**
в пул: режимы «Видео до 480/720/1080p» (H.264+AAC mp4) и «Только звук» (m4a).
Прогресс и отмена — в том же окне; окно можно закрыть, файл появится в пуле.
Квота пула действует: оценка размера до старта + жёсткий кап во время
скачивания. Бинарник yt-dlp приложение само скачивает с официального GitHub
в `storage/bin` при первом использовании (переопределяется `YTDLP_PATH` в
`.env`) и самообновляется, когда YouTube ломает старые версии.

> **Если ссылка распознаётся (название видно), а загрузка падает с ошибкой
> про видео-CDN** — сеть сервера блокирует `googlevideo.com` (типичная
> ситуация: youtube.com открывается, CDN — нет). Решение: задать прокси/VPN
> в `YTDLP_PROXY` в `.env` (http:// или socks5://) и перезапустить сервер.

**Поиск в Shikimori**: рядом с импортом по ссылке в менеджере медиа есть блок
поиска Shikimori — переключатель «Аниме / Персонажи», поле с дебаунсом ~300 мс
и живой дропдаун (мини-постер + факты: год · тип · рейтинг для аниме, имя
ru/en для персонажа). Клик «⬇ В пул» **синхронно** качает постер и добавляет
его в пул как обычную картинку (`Art`, с учётом квоты и роли). Базовый хост
задаётся `SHIKIMORI_BASE_URL` в `.env` (домен API периодически мигрирует —
смена одной переменной переносит интеграцию на новый хост); `SHIKIMORI_USER_AGENT`
задаёт заголовок User-Agent для запросов к API.

Скачивается **тот постер, который показан на сайте**, в полном разрешении:
старый REST-путь `/system/animes/original/<id>.jpg` отдаёт уменьшенную и иногда
устаревшую копию (например «Атака титанов»: 225×350 против 685×975 на сайте), а
актуальный файл берётся из GraphQL-поля `poster.originalUrl`
(`/uploads/poster/...`). Если свежий URL недоступен, импорт молча откатывается на
старый путь. Запросы к Shikimori соблюдают оба лимита сервиса (5 в секунду и 90 в
минуту): они выстраиваются в очередь со скользящим окном, а 429 повторяется с
паузой (с приоритетом заголовка `Retry-After`) — большие агентские сценарии на
сотни запросов больше не отваливаются по лимиту.

**Мои видео** (`/projects`) — проекты вне турнира: «Ручной топ» (тот же
конструктор, но позиции добавляются из пула — аудио или видео со звуком) и
«Пикер» (раунды: правило, 2–9 блоков с красивой сеткой — 5 это 3+2 по центру,
время показа, скрытие после показа, таймер с тик-звуком, фон-картинка/видео,
подписи и «правильный ответ»). Фоновая музыка пикера — **плейлист**: играет
непрерывно через все раунды, треки сменяются кроссфейдом ~1 с, по окончании
списка — луп; раунд со своей музыкой временно глушит плейлист. Подбор
фрагмента/старта — **на слух**: на позиции топа и видео-блоке пикера
раскрывается плеер исходника с кнопками «Старт отсюда» и «▶ Фрагмент»
(играет ровно выбранный кусок). Живое превью всего видео — в обоих
конструкторах.

**Интро и аутро пикера**: как и у топа, видео пикера может начинаться титульным
экраном и заканчиваться финальным (по 3 секунды каждый, тёмный фон + крупный
текст). Оба включаются галочками в «Настройках видео»; пустое поле текста берёт
название проекта (интро) и «Спасибо за просмотр» (аутро). Фоновая музыка играет
и на титрах. Новые проекты создаются с включёнными экранами, у ранее созданных
они выключены — чтобы уже собранные сценарии не поменяли длительность.

**Ориентация плиток пикера**: блоки раунда можно сделать **landscape** (16:9,
как раньше) или **portrait** (2:3, «вертикальные плашки» под формат
Shorts/Reels) — ориентация задаётся дефолтом на проекте и может быть
переопределена на конкретном раунде. Portrait-раскладка — отдельная сетка
«Ростер»: до 6 плиток в один ряд, 7–9 — два ряда (4+3 / 4+4 / 5+4), в отличие
от лендскейпа она не пытается сложить квадратный блок из пар рядов. Смена
эффективной ориентации сбрасывает недеструктивный кроп плитки (старый кроп
рассчитан под другие пропорции и был бы бессмысленным). У каждой плитки также
есть свой **режим вписывания** картинки/видео в рамку: `cover` (обрезка по
центру, по умолчанию), `fill` (растянуть на всю рамку, игнорируя пропорции)
и `contain` (вписать целиком, с полями/леттербоксом).

**Групповое сравнение (блок к блоку)**: у раунда есть режим — обычный (2–9
отдельных блоков, выбираем один) или **групповое сравнение**: 2–3 **блока** по
1–5 **карточек**, всего не больше 15. Так делаются раунды 3 на 3, 2 на 2 на 2 и
несимметричные вроде 3 против 2 или «один против трёх». В кадре блок — это
полупрозрачная плашка с названием (по умолчанию «Блок А/Б/В»), между плашками
знак **VS**. Размер карточки один на весь раунд: у блока с меньшим числом
карточек плашка просто уже — ни один персонаж не выглядит крупнее соседа. Блок
из 4–5 карточек сам переходит в два ряда, когда так карточка получается крупнее,
а блоки одного размера всегда выглядят одинаково. Шаг таймлайна — блок: за
«время показа блока» блок появляется целиком, карточки внутри выскакивают
каскадом по 0.15 с; `hideAfterReveal` гасит блок целиком. Правильный ответ
отмечается **на блоке** и не обязателен: плашка победителя светится золотом,
остальные гаснут. Если в блоке несколько видео со звуком — звучит первое, чтобы
не превращать раунд в шум. В конструкторе карточки переносятся между блоками
кнопками ⇦/⇨, порядок внутри блока — ←/→; групповой раунд попадает в видео, когда
в нём минимум два блока и в каждом есть карточка.

## MCP-сервер (ИИ сам собирает пикер)

Приложение умеет работать как **MCP-сервер** (stdio): внешний ИИ-клиент
(Claude Desktop / Claude Code) сам находит материал в Shikimori, импортирует
постеры и аудио в пул и раскладывает их по раундам проекта «Пикер». Рендер
остаётся в UI — инструменты возвращают ссылку `/projects/<id>`, вы проверяете
и рендерите проект сами.

### Запуск

MCP-сервер действует от имени одного аккаунта. Укажите его email и запустите:

```bash
# .env
MCP_ACTOR_EMAIL="you@example.com"   # email уже зарегистрированного аккаунта
# необязательно: папки, из которых ИИ может забирать медиа с диска (через ':')
MCP_LOCAL_MEDIA_DIRS="~/Музыка/ost:~/Картинки/фоны"

npm run mcp
```

Без `MCP_LOCAL_MEDIA_DIRS` инструменты `list_local_media`/`import_local_media`
отвечают `LOCAL_MEDIA_DISABLED`: доступа к диску по умолчанию нет. Путь вне
разрешённых папок (в том числе через `..` или симлинк) — `PATH_NOT_ALLOWED`.
Оригиналы файлов не перемещаются: в пул уходит копия.

Права и квоты берутся из роли этого аккаунта (импорт требует роль с
`media:upload`; размер пула ограничен квотой роли).

### Подключение из Claude Desktop / Claude Code

В конфиге MCP-клиента (например `claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "tournament-bracket-video": {
      "command": "npm",
      "args": ["run", "-s", "mcp"],
      "cwd": "/абсолютный/путь/к/tournament-bracket-video",
      "env": { "MCP_ACTOR_EMAIL": "you@example.com" }
    }
  }
}
```

| Инструмент | Назначение | Возвращает |
|---|---|---|
| `shikimori_find_studio` | найти студию по названию | `[{id, name}]` |
| `shikimori_studio_animes` | аниме студии (по популярности) | `[{id, type, label, posterPath, facts}]` |
| `shikimori_anime_characters` | персонажи аниме (по умолчанию Main) | `[{id, type, label, posterPath}]` |
| `shikimori_search` | поиск аниме/персонажа по названию | `[{id, type, label, posterPath, facts}]` |

| `import_youtube_audio` | скачать звук с YouTube (yt-dlp) в пул | `{artId}` |

| `add_round` | добавить раунд (вопрос/таймер/подписи); опционально `orientation` — переопределяет ориентацию только этого раунда, `mode: "groups"` — сразу групповое сравнение (раунд получает два пустых блока) | `{roundId, groupIds}` |
| `set_round` | изменить существующий раунд (промпт/таймер/подписи/ориентацию/`mode`); пустой `prompt` убирает вопрос; переключение `mode` раскладывает плитки по блокам и обратно | `{ok, groupIds}` |
| `add_group` | добавить блок в групповой раунд (≤ 3), опционально с названием | `{groupId}` |
| `set_group` | название блока и `isAnswer` — блок-победитель (один на раунд, необязателен) | `{ok}` |
| `delete_group` | удалить блок вместе с карточками | `{ok}` |
| `delete_round` | удалить раунд (например пустой стартовый — для чистого сценария) | `{ok}` |
| `add_tile` | плитка из готового арта: `roundId` для обычного раунда или `groupId` для блока; опционально `fitMode: "cover"|"fill"|"contain"` | `{tileId}` |
| `add_tile_from_shikimori` | импорт постера + карточка одним вызовом (`roundId` или `groupId`); опционально `fitMode` | `{tileId, artId}` |
| `set_playlist` | фоновая музыка пикера | `{ok}` |
| `set_project` | сам проект: задний фон (`backgroundArtId`, `null` снимает), название, ориентация, тексты интро/аутро, `revealSec`/`timerSec`/`hideAfterReveal`/`tickSound` | `{ok}` |
| `get_project` | структура проекта для самопроверки (тексты `intro`/`outro`, `background`, `playlistSec`, плановый `durationSec`, `mode` раундов и блоки) | `summary` |

### Пример сценария (студия Madhouse, 4 варианта, 10 раундов)

Попросите ИИ: «Собери пикер персонажей студии Madhouse, по 4 варианта в
раунде, 10 раундов, в каждом отметь одного как правильный ответ». ИИ сам:
`shikimori_find_studio("Madhouse")` → `shikimori_studio_animes` →
`shikimori_anime_characters` → `create_picker_project` → циклом `add_round` +
`add_tile_from_shikimori` (один `isAnswer: true`) → `get_project` для сверки →
отдаёт ссылку на проект. Дальше вы открываете `/projects/<id>` и рендерите.

### Пример сценария «по моему списку на Shikimori»

Попросите ИИ: «Собери пикер по аниме, которые я смотрел — ник `andrey03410`,
только с оценкой 9 и выше». ИИ вызывает
`shikimori_user_anime_list({user:"andrey03410", status:"completed", minScore:9})`,
отбрасывает записи с `kind` `music`/`pv`/`cm` (у них нет персонажей), берёт
персонажей каждого аниме через `shikimori_anime_characters` и раскладывает их по
раундам. `shikimori_user_favourites` даёт избранных персонажей и аниме того же
пользователя — их постеры импортируются напрямую. Сводка `countsByStatus`
показывает, сколько у человека просмотрено/запланировано/отложено/брошено.

### Пример сценария «сравни тройки»

Попросите ИИ: «Собери раунд: тройка персонажей Clannad против тройки AIR, ответ —
Clannad». ИИ вызывает `add_round({projectId, mode:"groups", prompt:"Какая тройка
сильнее?"})`, получает `groupIds`, называет блоки через `set_group`, наполняет их
`add_tile_from_shikimori({groupId, ...})` и отмечает победителя
`set_group({groupId, isAnswer:true})`. `get_project` показывает состав блоков.

### Пример сценария «оформи пикер»

Попросите ИИ: «Поставь фоном картинку с зонтиком из пула и подбери спокойный
плейлист под хронометраж». ИИ вызывает `get_project` (там плановый
`durationSec`), `list_pool({kind:"image"})` для фона →
`set_project({backgroundArtId})`, затем `list_local_media({dir})` →
`import_local_media({paths})` → `set_playlist({artIds})` и сверяет
`playlistSec` с `durationSec`.

## Структура

```
src/
  lib/domain/        # чистая доменная логика (движки, ранжирование, RMS, план видео) + тесты
  lib/               # upload (zip/id3), audio (ffmpeg), storage, render-assemble, db, api
  server/            # сервисы (tournaments, render) — серверные, используют Prisma
  remotion/          # Remotion-композиция (TopVideo) — рендер и предпросмотр

  integration/       # интеграционный тест на БД
prisma/schema.prisma # модель данных (обе фазы)
scripts/             # вспомогательные скрипты (e2e, очистка тестовых данных)
```

## Рендер видео

Рендер работает end-to-end (проверено: на выходе валидный MP4 H.264 1920×1080 @30fps).
Используется headless-режим `chrome-for-testing` с системным Chrome — путь задаётся
через `REMOTION_BROWSER_EXECUTABLE` (в `.env.example` указан `/usr/bin/google-chrome`).
Альтернатива — `npx remotion browser ensure` (скачает chrome-headless-shell). Детали:
[`.ai/research/remotion-headless-render.md`](.ai/research/remotion-headless-render.md).
