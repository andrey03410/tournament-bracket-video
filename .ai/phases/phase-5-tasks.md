## Задачи

- [x] T5.1 Схема: `User.role` (default "user"), `Track.sizeBytes`,
      `Art.sizeBytes` (+ `prisma db push` + перезапуск dev).
- [x] T5.2 Домен: `permissions.ts` — роли, пермишены, квоты, `can()`,
      `quotasFor()`; юнит-тесты.
- [x] T5.3 Auth: `requireUser()` → `{id,email,role}` из БД; `ADMIN_EMAILS`
      повышение при входе/регистрации; `userOr401`/`permissionOr403` в api.ts.
- [x] T5.4 Гейты: лимит турниров в транзакции, 100 МБ архива (заголовок+тело),

      `sizeBytes` при загрузках.
- [x] T5.5 Сервисы: `users.ts` (список с занятым местом, смена роли,
      удаление юзера с файлами), `account` usage (бэкфилл размеров).
- [x] T5.6 API: `/api/admin/users*`, `/api/account/usage`,
      `DELETE /api/render-jobs/[id]`.
- [x] T5.7 UI: welcome-экран для гостя, `/account` (профиль, квоты, архивы,
      пул, рендеры), `/admin`, топбар (кабинет/админка), скрытая кнопка
      рендера + подсказка, лимиты на форме создания.
- [x] T5.8 Интеграционные тесты всех сценариев спеки.
- [x] T5.9 Верификация вживую (гость/юзер/админ, негативные пробы) +
      README/CLAUDE.md/verify skill.

## Готово, когда

Гость упирается в welcome, юзер живёт в лимитах (1 архив ≤100 МБ, пул ≤100 МБ,
рендер 403) и управляет файлами в кабинете, админ управляет ролями и
пользователями, смена роли действует без перелогина, все сценарии спеки
зелёные по тестам.
