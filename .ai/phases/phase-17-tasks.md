# Фаза 17 — библиотека медиа — план реализации

**Goal:** Пул медиа выдерживает тысячи файлов: картинки приходят из сети и из
буфера обмена, файлы переименовываются с понятной обратной связью, личный
кабинет открывается мгновенно и позволяет убирать мусор пачками — не теряя при
этом карточки готовых проектов.

**Architecture:** Проверка ссылок, разбор буфера и формулировки использований —
чистые модули (`lib/domain/media-url.ts`, `clipboard.ts`, `art-usage.ts`),
скачивание и массовые операции — сервисный слой (`server/media-url.ts`,
`arts.ts`, `users.ts`), UI — общий хук `useMediaPool` с двумя представлениями
(`MediaBrowser`) и табы источников (`ImportSources`). Спека:
[`.ai/specs/17-media-library.md`](../specs/17-media-library.md).

## Global Constraints

- **Существующие пути импорта не ломаются**: yt-dlp-джобы для видео/аудио и
  импорт постеров Shikimori работают как раньше, включая MCP.
- **Никакого SSRF**: сервер ходит только на публичные `http(s)` адреса, лимит
  32 МБ и таймаут 15 с считаются по факту прочитанных байт, а не по заголовку.
- **Квота пула — в той же транзакции, что и вставка строки** (как в `createArt`):
  импорт по ссылке не должен обходить лимит роли.
- **Удаление честное**: пользователь до подтверждения видит, что удаление
  вынесет карточки из раундов и треки из плейлиста, а не только «освободит
  позиции».
- **Перед авторитетным `npm test` останавливать dev-сервер** (общий `prisma/dev.db`).
- Каждая задача закрывается тестами и уходит в `main` отдельным коммитом.
