# Фаза 1 — Декомпозиция на задачи

Спека: [`../specs/01-phase-tournament.md`](../specs/01-phase-tournament.md).

## MVP-решения по стеку (адаптация под запускаемость)

- БД: **Prisma + SQLite** для MVP (запуск без внешних сервисов). Продакшн-таргет —
  Postgres; в Prisma меняется `provider` + строка подключения.
- Auth: **Auth.js (next-auth)** credentials (email+пароль), сессии JWT, хеш bcrypt.
- Хранение аудио/арта: локальная ФС (`storage/`), пути в БД.
- Доменная логика вынесена в `src/lib/` (framework-agnostic) и покрыта unit-тестами.

## Задачи

- [x] T1.1 Скаффолд Next.js (App Router) + TS + Prisma + vitest.
- [x] T1.2 Prisma-схема: User, Tournament, Track, Comparison, Ranking (+ Фаза 2 модели).
- [x] T1.3 Auth: регистрация/вход (email+пароль), хеширование, сессия, guard.
- [x] T1.4 Доменный движок турнира:
  - merge/insertion сравнительная сортировка с **возобновляемым** состоянием;
  - swiss (фикс. раунды);
  - round-robin (все пары);
  - единый интерфейс `next pair / submit result / is done / ranking`.
- [x] T1.5 Ранжирование + тай-брейк (очки → прямое сравнение → победы → исходный порядок).
- [x] T1.6 Загрузка OST: разбор ZIP, извлечение названия (ID3 → имя файла), сохранение.
- [x] T1.7 API/сервисы: создать турнир, список, получить пару, отправить выбор,
  состояние сетки, финализация и top-N.
- [x] T1.8 UI: вход/регистрация, ЛК (список турниров), создание+загрузка, экран
  сравнения (плеер, лево/ничья/право, слепой/открытый), экран результата + выбор N.
- [x] T1.9 Unit-тесты доменной логики (движки, тай-брейк, разбор имён) — vitest.

## Готово, когда

Пользователь регистрируется, создаёт турнир из ZIP, проходит сравнения (с паузой),
получает упорядоченный топ, выбирает top-N; всё сохраняется. Доменная логика зелёная
по тестам.
