# Фаза 2 — Рендер видео

> Статус: спека после ревью user story (зафиксированы решения).
> Связано: [`00-vision.md`](00-vision.md), [`01-phase-tournament.md`](01-phase-tournament.md),
> [`../phases/README.md`](../phases/README.md).
> Предусловие: завершённый турнир из Фазы 1 с итоговым рейтингом и выбранным top-N.

## Цель фазы

По завершённому топу пользователь в **конструкторе** настраивает оформление каждого
OST (арт, фрагмент, длительность, активный сниппет), видит **живой предпросмотр**, затем
запускает **асинхронный рендер** видео (Remotion) и **скачивает** результат. Конфигурация
и отрендеренные видео сохраняются.

## In scope

- Конструктор оформления топа (на основе top-N из Фазы 1).
- Выбор арта на каждый OST (ручная загрузка + переиспользование).
- Настройка фрагмента: ручной таймлайн или «активный сниппет» (RMS-анализ).
- Глобальные настройки длительности/переходов + переопределение на OST.
- Интро/аутро экраны.
- Живой предпросмотр (Remotion Player).
- Асинхронный серверный рендер с прогрессом, сохранение и скачивание видео.
- Сохранение конфигурации, правка и повторный рендер.

## Out of scope (на старте)

- Несколько визуальных шаблонов/тем (архитектура закладывается, но в Фазе 2 — один
  шаблон).
- Вертикальный/квадратный формат (только 16:9).
- Облачный/распределённый рендер (Remotion Lambda) — рендерим локально на сервере.

## Зафиксированные решения

| Параметр              | Решение                                                       |
|-----------------------|---------------------------------------------------------------|
| Библиотека рендера    | Remotion (React-видео)                                        |
| Формат видео          | 16:9 горизонтальное, 1920x1080                                |
| Модель рендера        | Асинхронная задача + прогресс, скачивание по готовности       |
| Где рендерим          | Сервер (Remotion Node render), вывод на локальную ФС          |
| Арт                   | Ручная загрузка на каждый OST + переиспользование одного арта |
| Активный сниппет      | RMS-анализ энергии: окно заданной длины с макс. ср. энергией  |
| Порядок показа        | Обратный: от N к 1 (кульминация на #1)                        |
| Предпросмотр          | Живой, Remotion Player в браузере                             |
| Шаблон                | Один на старт, архитектура под несколько                      |
| Интро/аутро           | Есть: титульный экран + финальный экран                       |
| Конфиг рендера        | Сохраняется, правится, повторно рендерится; история рендеров  |

## Конструктор (на каждый OST)

Для каждого OST из top-N настраивается:

- **Арт**: загрузка изображения; можно назначить один арт нескольким OST
  (переиспользование). Если арт не задан — плейсхолдер/генерируемый фон *(открытый
  вопрос: подтвердить фолбэк)*.
- **Длительность фрагмента в видео**: берётся из глобального дефолта, можно
  переопределить для конкретного OST.
- **Фрагмент трека**:
  - ручной таймлайн (например `0:15 – 1:05`), **или**
  - галочка **«активный сниппет»** — система через RMS-анализ выбирает окно заданной
    длительности с максимальной средней энергией.

## Глобальные настройки видео

- Дефолтная длительность фрагмента (например 30 с), применяется ко всем OST как база.
- Пауза/переход между OST: **1 сек паузы с затуханием** (fade) между элементами.
- Интро (титульный экран с названием топа) и аутро (финальный экран) — текст
  редактируется.

## Анимация и подписи (плашка)

Подписи — **не плоский текст, а плашка с плавными появлениями/переходами**.

- **Формат подписи**: `N - Название композиции (Источник)` — например
  `5 - Roaring Tides (Clannad)` (место — название — источник).
- Состав подписи (выбрано): **номер места `#N`**, **название трека**,
  **исполнитель/источник**, плюс возможность **произвольной подписи/комментария**.
- Тайминг анимации одного элемента OST:
  1. **Арт** появляется плавно (fade-in), в конце элемента — плавно исчезает (fade-out).
  2. **Плашка с подписью** появляется через **~1 сек после появления арта**.
  3. Плашка держится **~5 сек**, затем плавно исчезает.
  4. Между OST — **1 сек паузы с затуханием**.

> Точные кривые/длительности анимаций финализируются при вёрстке Remotion-композиции;
> значения выше — отправная точка из ревью.

## Пайплайн рендера

1. Пользователь жмёт **«Рендер»** → создаётся фоновая задача рендера.
2. Сервер собирает Remotion-композицию из конфигурации (треки, фрагменты, арт,
   подписи, интро/аутро) и аудио-фрагментов.
3. UI показывает **прогресс**; рендер не блокирует интерфейс (можно уйти и вернуться).
4. По готовности видео сохраняется на ФС, появляется ссылка на **скачивание**.
5. Каждый рендер фиксируется в **истории рендеров** турнира.

> RMS-анализ для активного сниппета и нарезка/фейды аудио выполняются на сервере
> (библиотека извлечения/обработки аудио — открытый вопрос реализации, напр. ffmpeg).

## Связь конфига с турниром

- Конфигурация конструктора **привязана к турниру**, сохраняется и доступна для правки.
- Можно изменить настройки и **запустить рендер повторно**; прошлые рендеры остаются в
  истории.

## Черновая модель данных (дополнение к Фазе 1)

- `RenderConfig` — id, tournamentId, orientation (`16x9`), order (`desc`),
  defaultClipSec, transition settings, intro/outro (текст, вкл/выкл),
  template (`default`), updatedAt.
- `TrackRenderItem` — id, renderConfigId, trackId, rank, artId (nullable),
  clipMode (`manual` | `active_snippet`), clipStartSec/clipEndSec | snippetLenSec,
  customLabel (nullable).
- `Art` — id, userId, filePath (загруженные изображения, переиспользуемые между OST).
- `RenderJob` — id, tournamentId, renderConfigId, status (`queued` | `running` |
  `done` | `failed`), progress, outputPath (nullable), error (nullable), createdAt.

## Открытые вопросы к реализации

- Фолбэк арта при отсутствии (плейсхолдер vs генерируемый фон).
- Параметры RMS: размер анализирующего окна, шаг, обработка тишины/нормализация.
- Серверная обработка аудио (нарезка фрагмента + fade): инструмент (вероятно ffmpeg).
- Кодек/битрейт/качество вывода (предложение: H.264 mp4, 1080p; подтвердить).
- Точные тайминги/кривые анимаций плашки и арта.
- Управление очередью рендеров (один воркер vs параллельные задачи).
- Очистка старых рендеров/арта (ретеншн), т.к. видео хранятся на ФС.
