# Спецификация 13 — списки и избранное пользователя Shikimori в MCP

Статус: согласовано с владельцем продукта (2026-07-30). Реализовано в фазе 13.

## Цель

MCP-сервер умел искать аниме/персонажей и ходить по студиям, но ничего не знал о
**конкретном пользователе Shikimori**. Нужен сценарий «собери топ/пикер по тому,
что смотрел этот человек»: получить его список аниме с **его оценками и
статусами** (просмотрено / запланировано / смотрю / отложено / брошено /
пересматриваю) и его **избранное** (аниме и персонажи), чтобы дальше брать
персонажей из этих аниме уже существующим `shikimori_anime_characters`.

## Согласованные решения

| Вопрос                | Решение                                                                 |
|-----------------------|-------------------------------------------------------------------------|
| Идентификация юзера   | Ник (`/api/users/:nick?is_nickname=1`) или числовой id; ник тримится     |
| Нет такого юзера      | Ошибка `USER_NOT_FOUND` (HTTP 404 от API)                               |
| Список                | `/api/users/:id/anime_rates` одним запросом (`limit=5000`) — фильтр и сортировка локальные, поэтому «топ по оценке» честный по всему списку |
| Статусы               | `planned` \| `watching` \| `rewatching` \| `completed` \| `on_hold` \| `dropped` \| `all` (по умолчанию) |
| Оценка юзера          | `userScore` 1..10; API отдаёт `0` для неоценённого → `null`             |
| Порядок               | `score` (по умолчанию: оценка ↓, неоценённые в конец, тай — свежесть) \| `updated` \| `name` |
| Ответ                 | `{user, total, countsByStatus, matched, items}` — сводка по статусам даётся всегда |
| Лимит выдачи          | `limit` ≤ 500, по умолчанию 50                                          |
| Манга в списке        | Записи с `anime: null` (манга) в список аниме не попадают                |
| `kind` в выдаче       | Отдаётся структурно: у `music`/`pv`/`cm` персонажей нет, вызывающий их отфильтрует |
| Избранное             | Только `animes` и `characters` (манга/люди — вне сценария)               |
| Постеры избранного    | API отдаёт только `x64`-миниатюру → путь переписывается в `original` (и `preview` для превью), запрос-суффикс сохраняется |
| Записи без арта       | `/assets/globals/missing_original.jpg` → `posterPath: null` (такой файл не скачать) |
| Лимит запросов        | Запросы сериализуются с паузой 250 мс, 429 повторяется 2 раза (1 с, 2 с), затем `RATE_LIMITED` |
| Скоуп                 | Только MCP + сервисный слой; UI сайта не меняется                       |

## Слои

- `src/lib/domain/shikimori.ts` (чисто, без сети): `mapUser`, `mapUserRate`,
  `selectUserRates` (фильтр/порядок/лимит), `countByStatus`,
  `extractFavourites`, `resizeImagePath` (перевод пути между размерами +
  отсечение чужих/служебных путей). `mapAnimeResult`/`mapCharacterResult` теперь
  прогоняют пути картинок через `resizeImagePath`, поэтому плейсхолдер
  «нет арта» превращается в `null`.
- `src/lib/shikimori.ts` (сеть): `fetchUserRaw`, `fetchUserAnimeRatesRaw`,
  `fetchUserFavouritesRaw` + троттлинг и ретрай 429 в общем `getJson`.
- `src/server/shikimori.ts`: `findUser`, `userAnimeList`, `userFavourites`
  (DTO в том же формате, что поиск/дискавери — `posterPath` сразу годится для
  `import_shikimori_poster`).
- `src/mcp/server.ts`: инструменты `shikimori_find_user`,
  `shikimori_user_anime_list`, `shikimori_user_favourites`.

## Сценарий (для внешнего ИИ)

`shikimori_user_anime_list({user, status:"completed", minScore:9})` → отфильтровать
`kind` ≠ music/pv/cm → для каждого аниме `shikimori_anime_characters({animeId})` →
`create_picker_project` → `add_tile_from_shikimori` (или `import_shikimori_poster`
для ручного топа). Избранное — `shikimori_user_favourites`: его `posterPath`
готовы к импорту напрямую.

## Проверка

- Юнит (`src/lib/domain/shikimori.test.ts`): маппинг профиля/записи списка
  (score 0 → null, манга и неизвестные статусы отбрасываются), фильтры и три
  порядка, счётчики по статусам, избранное (x64 → original, мусор пропущен),
  `resizeImagePath` (в т.ч. отказ для чужого хоста/traversal и то, что результат
  проходит SSRF-гард), плейсхолдер «нет арта» → null.
- Интеграция (`src/integration/shikimori.integration.test.ts`): локальный
  HTTP-стенд вместо Shikimori — ник и id, `USER_NOT_FOUND`, список с оценками/
  статусами/счётчиками, фильтры и лимит, «список берётся одним запросом»,
  избранное с импортом постера в пул, ретрай 429 и явная ошибка после лимита.
- MCP e2e (`src/integration/mcp.e2e.test.ts`): по протоколу stdio — юзер →
  список 8+ → персонажи этого аниме → плитки; избранное → плитки.
- Живая проверка на реальном профиле `andrey03410` (443 записи: 319 просмотрено,
  95 запланировано, 15 отложено, 13 брошено, 1 смотрю; 61 избранный персонаж) —
  скрипты в scratchpad сессии 2026-07-30: сервисный смоук и прогон MCP по stdio
  против настоящего shikimori.io, включая импорт постера избранного персонажа.
