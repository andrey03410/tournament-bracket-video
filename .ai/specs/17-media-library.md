# Спецификация 17 — библиотека медиа: импорт картинок из сети, буфер обмена, разгруженный кабинет

Статус: согласовано с владельцем продукта (2026-07-31).

## Цель

Пул медиа превратился из «пары артов на топ» в библиотеку на тысячи файлов
(в рабочей базе 1322 картинки + 20 аудио). Три вещи, которые в этом масштабе
ломаются, и одна, которая опасна:

1. **Из сети можно принести только видео и аудио.** `POST /api/downloads`
   отдаёт ссылку yt-dlp, режимы `video`/`audio`. Картинку по ссылке положить
   некуда: единственный путь для картинок из сети — `POST
   /api/shikimori/import`, жёстко привязанный к хосту Shikimori
   (`isSafeImagePath`).
2. **Вставки из буфера нет вообще** — ни одного обработчика `paste`. Скриншот
   или скопированную в браузере картинку сначала надо сохранить в файл.
3. **Панель «Пул медиа» в личном кабинете рендерит весь пул одним списком.**
   `usageSummary()` при каждом заходе выбирает все арты с подсчётом
   использований, все рендеры с `stat()` на каждый файл, и отдаёт это в
   `AccountManager` — 1332 строки в DOM. Панели «Архивы» и «Рендеры» устроены
   так же.
4. **Переименование есть, но недоделано.** `renameArt` + `PATCH /api/arts/:id`
   работают, в модалке «Менеджер медиа» у карточки есть поле имени с
   сохранением по `blur`. Но: результат `fetch` игнорируется (ошибка молча
   теряется), нет ни отметки «сохранено», ни признака, что поле редактируемое,
   и в личном кабинете переименования нет вовсе.

Отдельно — дефект, найденный при разборе (**не** косметика):
`PickerTile.artId` и `PickerPlaylistItem.artId` объявлены с
`onDelete: Cascade`, а `usageCount` считает только `renderItems`. Удаление арта
из пула **молча удаляет карточку из раунда пикера** и трек из плейлиста, и
счётчик «используется в N позициях» показывает при этом ноль. С появлением
массового удаления это способ незаметно разобрать готовый проект.

## Согласованные решения

| Вопрос | Решение |
|---|---|
| Картинка по ссылке | Отдельный синхронный путь `POST /api/arts/from-url`: серверный `fetch` с таймаутом, проверкой `Content-Type: image/*` и лимитом 32 МБ. Без фоновой джобы — файл в пуле сразу |
| Поле ввода ссылки | Одно на все источники. Чистая функция `classifyMediaUrl` решает: картинка → `from-url`, иначе → существующий `DownloadJob` (yt-dlp). Селектор качества показывается только для не-картинок |
| Если сервер ответил «это не картинка» | Кнопка-фолбэк «Скачать как видео/аудио» — тот же URL уходит в `DownloadJob`, повторно набирать не нужно |
| Безопасность импорта | Только `http`/`https`; `Content-Type` должен быть `image/*` и совпадать по типу с расширением; лимит 32 МБ (по `Content-Length` и по факту прочитанных байт); таймаут 15 с; не больше 3 редиректов, каждый хост резолвится и отвергается, если ведёт в приватный диапазон (SSRF) |
| Медиа в локальной сети | По умолчанию приватные адреса запрещены. Установка «для себя», которая держит картинки на NAS, включает их через `MEDIA_URL_ALLOW_PRIVATE=1` — тем же переключателем пользуются тесты со своим фикстур-сервером |
| Буфер обмена | `Ctrl+V` внутри модалки медиа. Приоритет: файлы из `clipboardData` → загрузка как обычных файлов; иначе `text/html` → первый `<img src>`; иначе `text/plain` → если это URL картинки, импорт по ссылке. Когда фокус в текстовом поле, перехвата нет |
| Имя вставленного скриншота | Буфер отдаёт `image.png`; такое (и пустое) имя заменяется на «Вставка ДД.ММ ЧЧ:ММ», карточка встаёт первой в сетке и сразу готова к переименованию |
| Переименование | Инлайн: подпись карточки — поле с видимым карандашом, `Enter`/`blur` сохраняют, `Esc` отменяет, на успех — «✓ сохранено» на 1.5 с, на ошибку — текст ошибки и откат к прежнему значению. Тот же механизм в личном кабинете |
| Источники в модалке | Табы над сеткой: «Файлы · Ссылка · Shikimori». Активный источник занимает одну компактную полосу, сетка пула начинается сразу под ним. Вставка из буфера работает на любом табе |
| Пул в кабинете | Панель показывает сводку (сколько файлов, сколько занято, разбивка картинки/видео/аудио) и кнопку «Показать все». По раскрытию — тот же список, что в менеджере: страницами через существующий `GET /api/arts` (курсор, поиск, фильтр по типу), с миниатюрами, переименованием и удалением |
| «Архивы» и «Рендеры» в кабинете | Тот же приём: сводка + «Показать все» с ленивой загрузкой. `usageSummary()` больше не выбирает строки — только агрегаты |
| Размер рендера | `RenderJob.outputBytes` (заполняется при завершении рендера, ленивый бэкофилл для старых строк) вместо `stat()` на каждый файл при каждом заходе в кабинет |
| Мультивыбор | Чекбокс в углу карточки/строки, `Shift`-клик выделяет диапазон, панель «Выбрано N» с «Удалить выбранные» и «Снять выделение». Лимит одной операции — 200 файлов |
| Честный счётчик использований | `usageCount` = позиции топов + карточки пикера + элементы плейлиста + фоны и музыка проектов/раундов, с разбивкой. Подтверждение удаления называет последствия словами: «3 карточки в раундах будут удалены, 1 позиция топа освободится» |
| Каскад не меняем | `PickerTile`/`PickerPlaylistItem` остаются на `Cascade` (карточка без арта бессмысленна), но пользователь предупреждён до удаления, а не после |
| «Недавние» | Менять не нужно: `lastUsedAt` уже проставляется и при добавлении карточки в раунд (`addTile`/`addTileToGroup`), и при назначении на позицию топа — проверено по коду при реализации фазы |
| Место работы с пулом | Без новых страниц: модалка из конструкторов, как сейчас, плюс тот же список в кабинете |

## Модель данных

```prisma
model RenderJob {
  outputBytes Float?  // размер MP4; null = ещё не считали (ленивый бэкофилл)
}
```

Больше миграций нет: `Art` не меняется, дедупликация по хешу в эту фазу не
входит.

## Слои

Чистый домен (`src/lib/domain/`):

- `media-url.ts` — `classifyMediaUrl(url)` → `"image" | "media" | null`
  (расширение пути, регистр и query-string не мешают); `imageExtFromContentType`
  → `".jpg" | ".png" | ".webp" | ".gif" | null`; `isBlockedHostname` (localhost,
  `*.local`, `*.internal`); `isBlockedAddress` (127/8, 10/8, 172.16/12,
  192.168/16, 169.254/16, `::1`, `fc00::/7`, `fe80::/10`, `0.0.0.0`);
  `urlLabel(url)` — имя из последнего сегмента без расширения, с
  `decodeURIComponent` и обрезкой до 200 символов.
- `clipboard.ts` — `pickPastedImageUrl({text, html})` (сначала `<img src>` из
  HTML, затем текстовый URL; иначе `null`), `pasteLabel(date)` →
  «Вставка 31.07 18:20», `isGenericPasteName(name)` (`image.png`, `unknown`,
  пустое).
- `art-usage.ts` — `usageBreakdown(counts)` → `{positions, cards, playlist,
  backgrounds, total}` и `describeUsage(breakdown)` → строка для подтверждения
  удаления.

Сервисный слой (`src/server/`):

- `media-url.ts` — `importImageFromUrl(userId, {url, label, maxPoolBytes})`:
  валидация, потоковое скачивание в `storage/tmp` с обрывом по лимиту, затем
  существующий `createArtFromFile` (он переносит файл и считает квоту в
  транзакции). Ошибки: `BAD_URL`, `BLOCKED_HOST`, `NOT_IMAGE`, `TOO_LARGE`,
  `FETCH_FAILED`, `POOL_QUOTA`.
- `arts.ts` — `ArtRow.usage` (разбивка через `_count` по всем восьми связям
  `Art`), `deleteArts(userId, ids)` → `{deleted, failed}` поверх существующего
  `deleteArt`, лимит 200.
- `users.ts` — `usageSummary` только на агрегатах (`aggregate`/`count`, без
  выборки строк): пул по типам, архивы, рендеры; `listRenderJobs(userId,
  {cursor, limit})` с ленивым бэкофиллом `outputBytes`.
- `render.ts` — записывает `outputBytes` при переводе джобы в `done`.

Роуты:

- `POST /api/arts/from-url` — `{url, label?}` → DTO арта; право `media:upload`,
  квота роли, сообщения об ошибках по таблице выше.
- `DELETE /api/arts` — `{ids: string[]}` → `{deleted, failed}`.
- `GET /api/account/renders?cursor=` — страница рендеров для кабинета.
- `GET /api/arts` — в DTO добавляется `usage` (разбивка); `usageCount`
  становится полной суммой.

UI:

- `src/app/components/useMediaPool.ts` — общий хук: страницы, поиск, фильтр по
  типу, переименование, удаление (одиночное и массовое), выделение с
  `Shift`-диапазоном.
- `src/app/components/MediaBrowser.tsx` — представление поверх хука,
  `view="grid" | "rows"`: сетка для менеджера, компактные строки с миниатюрой
  для кабинета.
- `src/app/components/ImportSources.tsx` — табы «Файлы · Ссылка · Shikimori»
  (существующие `UrlImportPanel`/`ShikimoriPanel` переезжают внутрь) и
  обработчик вставки из буфера.
- `ArtGalleryModal` — использует `ImportSources`; в `mode="manage"` сетка идёт
  из `MediaBrowser`, режимы `pick`/`crop` работают как раньше.
- `AccountManager` — три панели-сводки с «Показать все»; пул раскрывается в
  `MediaBrowser view="rows"`.

## Сценарии

- **Картинка по ссылке.** Менеджер медиа → таб «Ссылка» → вставить адрес
  картинки → «Скачать» → карточка в сетке через секунду. Если по адресу видео —
  то же поле уходит в фоновую загрузку с выбором качества.
- **Скриншот.** Вырезать область экрана → открыть модалку → `Ctrl+V` → в пуле
  «Вставка 31.07 18:20» → переименовать на месте.
- **Уборка.** Кабинет → «Пул медиа: 1332 файла, 213 МБ» → «Показать все» →
  фильтр «Картинки», поиск по названию → выделить десяток `Shift`-кликом →
  «Удалить выбранные» → подтверждение честно говорит, что 4 из них стоят
  карточками в раундах.

## Проверка

- Юнит `media-url.test.ts`: классификация (`.JPG?x=1` → картинка, `.mp4` и
  адрес без расширения → media, `ftp://` → null), `Content-Type` → расширение,
  блокировка localhost/приватных диапазонов и пропуск публичного адреса, метка
  из пути с `%20`.
- Юнит `clipboard.test.ts`: приоритет HTML `<img src>` над текстом, текстовый
  URL картинки, посторонний текст → `null`, формат метки вставки, распознавание
  безымянных файлов.
- Юнит `art-usage.test.ts`: сумма и формулировки разбивки (в том числе «не
  используется»).
- Интеграция `media-url.integration.test.ts` (локальный HTTP-сервер): успешный
  импорт создаёт арт с правильным `kind`/`sizeBytes`, HTML вместо картинки →
  `NOT_IMAGE`, превышение лимита обрывается → `TOO_LARGE`, редирект на
  `127.0.0.1` → `BLOCKED_HOST`, переполнение квоты → `POOL_QUOTA` без осиротевших
  файлов.
- Интеграция `arts.integration.test.ts`: разбивка использований по всем видам
  ссылок, массовое удаление (частичный отказ на чужой арт, каскадное удаление
  карточки пикера, освобождение позиции топа), лимит 200.
- Интеграция `users.integration.test.ts`: `usageSummary` без списков, агрегаты
  сходятся с фактическими суммами; страница рендеров с курсором и бэкофиллом
  `outputBytes`.
- HTTP E2E: `POST /api/arts/from-url` (401 гостю, 403 роли без `media:upload`,
  400 на мусорный URL, 200 и файл в пуле), `DELETE /api/arts` пачкой,
  `GET /api/account/renders`.
- UI-прогон (headless Chrome): вставка синтетическим `ClipboardEvent` (файл и
  ссылка), таб «Ссылка» → карточка появилась, переименование с индикацией
  «сохранено» и с ошибкой, мультивыбор `Shift`-кликом и массовое удаление,
  кабинет — сводка, «Показать все», докрутка второй страницы.
- Живая проверка: рендер существующего пикера после уборки пула не деградировал
  (кадры на месте), время загрузки `/account` до и после.
