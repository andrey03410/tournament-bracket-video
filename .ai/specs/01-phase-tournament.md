# Фаза 1 — Турнирная сетка

> Статус: спека после ревью user story (зафиксированы решения).
> Связано: [`00-vision.md`](00-vision.md), [`../phases/README.md`](../phases/README.md).

## Цель фазы

Авторизованный пользователь загружает набор OST, выбирает турнирную схему, проходит
серию попарных сравнений (1 на 1) с прослушиванием, по ходу видит актуальное состояние
сетки, по завершении получает упорядоченный топ. Турниры и итоговые топы сохраняются в
личном кабинете. Переход к рендеру — Фаза 2 (вне scope).

## In scope

- Регистрация/вход (email + пароль).
- Личный кабинет со списком турниров.
- Создание турнира: загрузка OST, настройки, выбор схемы.
- Движок попарных сравнений с прослушиванием и выбором лево/право/ничья.
- Сохранение прогресса (пауза/возобновление).
- Формирование и просмотр итогового рейтинга, выбор размера топа (top-N).

## Out of scope (Фаза 2)

- Конструктор оформления (арт, фрагменты, активный сниппет).
- Рендер видео и скачивание.

## Загрузка OST

- Формат загрузки: **ZIP-архив** с аудиофайлами.
- Поддерживаемые форматы аудио (старт): `mp3`, `m4a/aac`, `flac`, `wav`, `ogg`.
- Название трека: из **ID3/метаданных**; фолбэк — имя файла (без расширения).
  Название можно отредактировать вручную перед стартом турнира.
- После распаковки показывается список треков с возможностью удалить лишние/
  переименовать перед стартом.
- Файлы сохраняются на ФС сервера, метаданные (имя, путь, длительность, исполнитель)
  — в БД, привязка к турниру и пользователю.

> Открытые лимиты (предложение, подтвердить при реализации): размер файла ≤ ~25 МБ,
> число треков ≤ ~64 на турнир, размер архива ≤ ~500 МБ.

## Турнирные схемы (выбор при создании)

Пользователь выбирает одну из схем. Поддерживаются:

1. **Сравнительная сортировка (merge/insertion)** — алгоритм сам подбирает пары для
   получения ПОЛНОГО упорядоченного списка за ~N·log N сравнений. Основной режим для
   точного топа.
2. **Швейцарка (Swiss)** — фиксированное число раундов, пары по текущему счёту. Меньше
   сравнений, ранжирование приблизительное.
3. **Круговая (round-robin)** — все пары. Максимально точно, но число сравнений растёт
   квадратично (для 50 — 1225). При выборе для большого набора показывать
   предупреждение об объёме.

### Ничьи

- Ничьи **разрешены**, **но без деления мест**.
- Ничья влияет на счёт (трактуется как равенство, напр. 0.5/0.5 в Swiss/round-robin;
  в сравнительной сортировке — как «равны» при слиянии).
- Итоговый рейтинг **строго упорядочен**: равные по очкам разводятся доп. критерием
  (тай-брейк). Предлагаемый порядок тай-брейка: (1) очки, (2) результат прямого
  сравнения, если было, (3) число побед, (4) исходный порядок загрузки. Финализировать
  при реализации движка.

## Экран сравнения 1-на-1

- Два варианта (A/B), у каждого — аудиоплеер для прослушивания.
- Кнопки: **Лево / Ничья / Право**.
- Режим показа метаданных — **переключаемый, задаётся при создании турнира**:
  - *Слепой*: названия/арт скрыты во время выбора (судим по музыке), можно раскрыть
    после выбора.
  - *Открытый*: названия и метаданные видны сразу.
- По ходу турнира доступен просмотр **актуального состояния сетки/рейтинга** и
  прогресс (сколько сравнений сделано / осталось — приблизительно для адаптивных схем).

## Сессии и личный кабинет

- В ЛК — **несколько турниров**, каждый со статусом (черновик / в процессе /
  завершён).
- **Пауза/возобновление**: прогресс сравнений сохраняется на сервере после каждого
  выбора; можно выйти и вернуться к незавершённому турниру.
- Завершённый турнир хранит итоговый рейтинг и доступен для перехода к рендеру (Фаза 2).

## Размер топа (top-N)

- Сравниваются/ранжируются **все** загруженные OST → полный рейтинг.
- Размер топа N задаётся **после** турнира на экране результата и может быть изменён
  (например, top-30 из 50). N влияет на то, что уйдёт в рендер в Фазе 2.

## Черновая модель данных (уточняется при реализации)

- `User` — id, email, passwordHash, createdAt.
- `Tournament` — id, userId, title, scheme (`merge` | `swiss` | `round_robin`),
  blindMode (bool), status (`draft` | `in_progress` | `completed`), topSize (nullable),
  createdAt, updatedAt.
- `Track` — id, tournamentId, title, artist (nullable), filePath, durationSec, order.
- `Comparison` — id, tournamentId, trackAId, trackBId, result (`a` | `b` | `draw`),
  createdAt. (+ состояние движка/очередь пар — формат зависит от схемы.)
- `Ranking` — итоговый порядок (trackId → rank/score), формируется при завершении.

## Открытые вопросы к реализации

- Точная формула тай-брейка для каждой схемы.
- Число раундов Swiss (формула от N) и условие завершения.
- Хранение внутреннего состояния адаптивного алгоритма (merge/insertion) между
  сессиями для корректного возобновления.
- Конкретные лимиты загрузки (см. выше).
- Извлечение длительности/метаданных аудио на сервере (библиотека).
