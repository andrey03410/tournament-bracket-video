# Спецификация 12 — интро и аутро в пикере

Статус: согласовано с владельцем продукта (2026-07-30). Реализовано в фазе 12.

## Цель

У режима «Пикер» не было вступительного и финального экранов — видео начиналось
сразу с первого раунда и обрывалось после последнего. В «топах» такие экраны
есть (`RenderConfig.introEnabled/introText/outroEnabled/outroText`). Даём пикеру
то же самое, теми же понятиями и с той же длительностью.

## Согласованные решения

| Вопрос                 | Решение                                                                 |
|------------------------|-------------------------------------------------------------------------|
| Где хранится           | Поля на `VideoProject` (у пикера нет `RenderConfig`)                    |
| Длительность           | 3 сек на экран, как в топах (не настраивается)                          |
| Оформление             | Тот же титульный экран, что в топах — тёмный фон, крупный текст, фейд-ин |
| Текст интро по умолч.  | Название проекта (если поле пустое)                                     |
| Текст аутро по умолч.  | «Спасибо за просмотр»                                                   |
| Фоновая музыка         | Плейлист играет и на интро/аутро (непрерывность звука)                  |
| Обратная совместимость | Колонки `@default(false)`: старые пикеры не меняют таймлайн; новые проекты создаются с включёнными экранами |
| Пустой проект          | Без ни одного рендерящегося раунда экраны не добавляются вовсе          |
| MCP                    | `create_picker_project` принимает `introText`/`outroText` (пустая строка = выключить), `get_project` отдаёт `intro`/`outro` |

## Данные (Prisma, `prisma db push`)

`VideoProject` расширяется четырьмя полями (пикерные «книжные подпорки»; у топов
эти же настройки живут в `RenderConfig`):

- `introEnabled Boolean @default(false)`, `introText String?`
- `outroEnabled Boolean @default(false)`, `outroText String?`

Валидация в сервисном слое: текст тримится, пустой → `null` (сработает дефолт),
длиннее 120 символов → `BAD_BOOKEND_TEXT`.

## План (`src/lib/domain/picker-plan.ts`)

- Константа `BOOKEND_SEC = 3`.
- `buildPickerPlan(defaults, rounds, playlist, bookends)` — четвёртый аргумент
  `BookendsInput = { intro: { text } | null, outro: { text } | null }`
  (по умолчанию оба `null`, поэтому старые вызовы не меняются).
- Курсор таймлайна стартует не с 0, а с `introSec`: все раунды и плитки
  сдвигаются на длину интро без изменения внутренней математики раунда.
- `plan.intro` / `plan.outro`: `{ text, fromSec, durationSec }` или `null`.
  `outro.fromSec` = конец последнего раунда; `durationSec` видео включает аутро.
- Если ни в одном раунде нет плиток — экраны не добавляются (пустой проект
  остаётся пустым таймлайном, конструктор показывает подсказку).
- Окна `muteWindows` не расширяются: плейлист звучит и на титрах.

## Композиция (Remotion)

Карточка титров вынесена из `TopVideo.tsx` в `src/remotion/TitleCard.tsx` и
используется обеими композициями (`TopVideo`, `PickerVideo`) — единое
оформление интро/аутро для топов и пикера.

## UI и API

- `PATCH /api/projects/:id` принимает `introEnabled`, `introText`,
  `outroEnabled`, `outroText`; GET отдаёт их в DTO проекта.
- Конструктор пикера: в блоке «Настройки видео» два чекбокса с текстовыми
  полями (плейсхолдеры показывают дефолты) — паттерн из конструктора топа.
