# Спецификация 16 — групповое сравнение в пикере (блок против блока)

Статус: согласовано с владельцем продукта (2026-07-31). Реализовано в фазе 16.

## Цель

Сейчас раунд пикера — это 2–9 отдельных плиток: «выбери одного». Нужен второй
тип раунда: **сравнение блоков** — 3 на 3, 2 на 2 на 2, а также несимметричные
составы (3 против 2, один против трёх). Блок читается как одно целое: у него
своя плашка, название и, если нужно, отметка «победитель».

## Терминология

В групповом режиме **блок** — это группа карточек (панель с названием),
**карточка** — одна единица медиа внутри блока. В обычном режиме интерфейс
по-прежнему называет плитку «блоком» (существующие подписи не меняются).

## Согласованные решения

| Вопрос | Решение |
|---|---|
| Режим раунда | `mode`: `single` (как сейчас) или `groups`; режимы мешаются в одном проекте |
| Лимиты | 2–3 блока в раунде, 1–5 карточек в блоке, всего ≤ 15 карточек |
| Несимметричность | Разрешена, вплоть до блока из одной карточки («один против трёх») |
| Размер карточки | Один на весь раунд: ни один персонаж не крупнее другого; ширина плашки — по числу колонок блока |
| Внутренняя раскладка блока | Блок из 1–3 карточек всегда один ряд; 4 и 5 перебирают `[4]`/`[2,2]` и `[5]`/`[3,2]` и берут вариант, где карточка крупнее. Блоки одного размера получают одинаковое разбиение |
| Расположение блоков | Всегда рядом по горизонтали, композиция центрируется в кадре |
| Разделитель | Полупрозрачная панель с рамкой + название сверху; между панелями знак «VS» (при трёх блоках — в каждом зазоре) |
| Показ | Шаг таймлайна = блок: окно блока `revealSec`, внутри карточки каскадом по 0.15 с (последняя успевает внутри окна) |
| `hideAfterReveal` | Применяется к блоку целиком |
| Правильный ответ | Отмечается блок (`isAnswer`); ответ **необязателен** — раунд без ответа остаётся честным «выбери сам» |
| Фаза ответа | Панель-победитель светится золотом и слегка увеличивается, остальные гаснут до 25% (тот же язык, что у карточки-ответа) |
| Подписи | Название блока видно всегда; подписи карточек — по существующему `labelsMode` раунда |
| Звук карточек | В блоке звучит первая карточка с видео+звуком, остальные молчат; дакинг фоновой музыки — одно окно на блок |
| Таймер, тик, промпт, фон, музыка | Как в обычном раунде |
| Кропы | Не сбрасываются: пропорция карточки задаётся ориентацией (16:9 / 2:3), меняется только масштаб |
| Переключение режима | Существующие плитки уезжают в блок 1, вторым создаётся пустой блок; карточки переносятся между блоками стрелками |
| Валидация рендера | Групповому раунду нужно ≥ 2 блоков и ≥ 1 карточки в каждом; иначе раунд помечается как неготовый (как сейчас при < 2 плиток) |
| Мелкие карточки | Мягкая подсказка в конструкторе, если карточек много в портретной ориентации (запрета нет) |
| MCP | `add_group`/`set_group`/`delete_group`; `add_round` принимает `mode`, `add_tile`/`add_tile_from_shikimori` — `groupId` вместо `roundId`; `get_project` показывает блоки |

## Модель данных

```prisma
model PickerRound {
  mode   String        @default("single") // "single" | "groups"
  groups PickerGroup[]
}

model PickerGroup {
  id       String  @id @default(cuid())
  roundId  String
  order    Int
  label    String?          // null = «Блок А/Б/В» по порядку
  isAnswer Boolean @default(false)
  tiles    PickerTile[]
}

model PickerTile {
  groupId String?            // null = плитка обычного раунда
}
```

Удаление блока каскадом удаляет его карточки. `PickerTile.order` в групповом
раунде упорядочивает карточки внутри блока. `PickerTile.isAnswer` в групповом
режиме игнорируется (ответ живёт на блоке).

## Слои

- `src/lib/domain/picker-layout.ts`: новая чистая функция
  `groupLayout(counts: number[], orientation)` → `{ cardW, cardH, panels: TileRect[],
  cards: TileRect[][] }`. Зона кадра, зазоры и пропорция карточки — те же
  константы, что у `pickerLayout`; у панели есть внутренний отступ и полоса под
  название.
- `src/lib/domain/picker-plan.ts`: `PlanRound.mode` и `PlanRound.groups:
  PlanGroup[]` (`{index, label, isAnswer, panel, revealAtSec, hideAtSec, tiles}`).
  Таймлайн группового раунда: `finaleAtSec = startSec + introSec + blocks *
  revealSec`, окно блока `revealSec`, карточка `i` внутри блока стартует со
  сдвигом `min(0.15, (revealSec - 0.3) / (n - 1)) * i`, ответ и `endSec` — по
  существующим правилам.
- `src/server/projects.ts`: `setRoundMode` (переключение с переносом плиток),
  `addGroup`, `patchGroup`, `deleteGroup`, `moveTileToGroup`; `addTile`
  принимает блок; лимиты и валидация.
- `src/server/picker-render.ts`: превью-план и подготовка ассетов по блокам
  (`tile-<ri>-g<gi>-<ti>`), `roundIsRenderable` — общее правило для
  `invalidRounds` и гарда рендера.
- `src/remotion/PickerVideo.tsx`: панель блока (рамка, название, свечение
  ответа), знак VS в зазорах, каскад карточек.
- `src/app/projects/[id]/PickerConstructor.tsx`: переключатель режима, колонки
  блоков, перенос карточек (⇦/⇨) и порядок внутри блока (←/→ поверх
  `reorderGroupTiles`), отметка ответа, подсказки валидации.
- `src/mcp/server.ts` + `src/mcp/project-summary.ts`: инструменты и сводка.

## Сценарий (пользователь)

Раунд → «Групповое сравнение» → блок А получает уже добавленные карточки, блок Б
создаётся пустым → «+ карточка» из пула (или через MCP из Shikimori) → название
блоков («Тройка Клэннад», «Тройка AIR») → отметить блок-победитель (или не
отмечать) → превью → рендер.
