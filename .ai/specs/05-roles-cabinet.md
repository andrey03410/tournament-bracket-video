# Спецификация 05 — Роли, пермишены, личный кабинет, админка

Статус: согласовано с владельцем продукта (2026-07-10), реализуется в фазе 5.

## Цель

Отделить общедоступный контент от админки: гость видит только приветственный
экран, авторизованный пользователь работает с лимитами, админ может всё.
Личный кабинет даёт пользователю управление своими файлами на сервере.

## Согласованные решения

| Вопрос                        | Решение                                                          |
|-------------------------------|------------------------------------------------------------------|
| Модель прав                   | Поле `role` у User + матрица «роль → пермишены/квоты» в коде     |
| Бутстрап админа               | `ADMIN_EMAILS` в `.env` (авто-повышение при входе) + смена ролей в админке |
| Лимит «1 архив» юзера         | 1 активный турнир одновременно; удаление освобождает слот        |
| Рендер для юзера              | Конструктор и живое превью доступны; запуск MP4-рендера — 403    |
| Регистрация                   | Открытая; новые аккаунты получают роль `user`                    |
| Пул медиа для юзера           | Разрешён, суммарная квота 100 МБ                                 |
| Админка                       | Список пользователей + смена ролей + удаление (с файлами)        |
| Личный кабинет                | Архивы + пул медиа + рендеры, с размерами и удалением + профиль  |

## Роли и пермишены

Роли (строка в БД, расширяемо): `user` (default), `admin`. Гость — отсутствие
сессии, в матрице представлен виртуальной ролью `guest` с пустым набором прав.

Матрица — чистый модуль `src/lib/domain/permissions.ts`:

```
Permission = "tournament:create" | "render:run" | "media:upload" | "admin:users"

guest: []
user:  [tournament:create, media:upload]
admin: [tournament:create, media:upload, render:run, admin:users]
```

Квоты там же (`null` = без лимита):

```
Quotas = { maxTournaments, maxArchiveBytes, maxPoolBytes }
user:  { maxTournaments: 1, maxArchiveBytes: 100 МБ, maxPoolBytes: 100 МБ }
admin: { maxTournaments: null, maxArchiveBytes: 2 ГБ, maxPoolBytes: null }
```

Проверки в коде — **только по пермишенам и квотам**, не по имени роли.
Новая роль = одна запись в матрице.

### Актуальность роли (критический кейс)

Сессия — JWT; роль в токене протухнет при смене админом. Поэтому роль
**не хранится в JWT**: `requireUser()` резолвит `{ id, email, role }` свежим
чтением из БД на каждый запрос (SQLite, дёшево). Понижение/повышение действует
со следующего запроса без перелогина.

### Бутстрап админа

`ADMIN_EMAILS` — список email через запятую. При `authorize` (вход) и при
регистрации: если email в списке и роль в БД ниже — она поднимается до `admin`
и персистится. Переживает пересоздание базы. По умолчанию в `.env`:
`andrey.gel001234@mail.ru`.

## Гость

- `/` — приветственный экран: что умеет сайт (турниры, схемы, слепой режим,
  видео, конструктор, рендер), CTA «Войти» и «Зарегистрироваться».
- Авторизованный на `/` — редирект на `/tournaments` (как сейчас).
- Все прочие страницы для гостя — редирект на `/`; все API — 401 (уже так).

## Лимиты пользователя (роль `user`)

- **Архив**: не более `maxTournaments` (1) одновременно. Превышение → 403
  «Достигнут лимит архивов. Удалите существующий в личном кабинете».
  Проверка числа турниров — внутри транзакции создания (гонка двух
  параллельных загрузок не пробивает лимит).
- **Размер архива**: ≤ 100 МБ. Проверяются и `Content-Length`, и фактический
  размер тела (заниженный заголовок не обходит лимит) → 413.
- **Пул медиа**: суммарный размер файлов пользователя в пуле ≤ 100 МБ → 413
  при превышении. Размер файла храним в `Art.sizeBytes` (заполняется при
  загрузке), квота считается суммой по БД.
- **Рендер**: `POST /api/tournaments/[id]/render` (и повтор) без `render:run`
  → 403 «Рендер доступен только администратору». Кнопка в UI скрыта, вместо
  неё подсказка. Конструктор, превью, пул, кроп — доступны.
- Смена роли задним числом: существующие турниры/файлы не трогаем; новые
  загрузки блокируются, пока факт не станет ≤ лимита.

## Личный кабинет `/account`

- Профиль: email, роль (бейдж), квоты «занято X из Y» (архивы и пул).
- **Менеджер архивов**: список турниров с размером на диске (сумма треков),
  статусом, числом треков; удаление с подтверждением → файлы стираются с
  сервера (уже реализовано в `deleteTournament`) и слот освобождается.
- **Пул медиа**: список с размерами, удаление (существующая логика
  `deleteArt` — освобождает позиции и постер).
- **Рендеры**: готовые MP4 с размером, скачивание и удаление.
- Ссылка «Личный кабинет» в топбаре.

Размеры: у новых файлов — из `sizeBytes` (Track/Art); для существующих строк
без размера — ленивый `stat` с бэкфиллом в БД.

## Админка `/admin`

Доступ по пермишену `admin:users` (страница и API; иначе 404/403).

- Таблица пользователей: email, роль (select), число турниров, занято на
  диске, дата регистрации.
- Смена роли — немедленно (роль читается из БД на каждый запрос).
- Удаление пользователя: подтверждение → с диска стираются его турниры,
  пул (`storage/arts/<userId>`), выходные рендеры; затем каскадное удаление
  в БД. **Самого себя удалить или понизить нельзя** (403) — защита от
  выпиливания последнего админа.

## API

- `src/lib/api.ts`: `userOr401()` теперь возвращает `{ user: { id, email,
  role } }`; новый `permissionOr403(perm)`.
- Новые роуты: `GET/PATCH/DELETE /api/admin/users[/id]`,
  `GET /api/account/usage`, `DELETE /api/render-jobs/[id]`.
- Ошибки — человекочитаемые русские тексты, коды 401/403/413.

## Тесты

Юнит (`permissions.test.ts`): матрица ролей, `can()`, квоты, неизвестная роль
= права гостя.

Интеграционные (реальная БД):
- регистрация → роль `user`; email из `ADMIN_EMAILS` → `admin` при входе;
- юзер: 2-й турнир → 403; удалил → создать можно; архив 101 МБ → 413;
- гонка: два параллельных создания при пустом слоте → ровно один успех;
- рендер юзером → 403, админом — проходит;
- пул: превышение суммарных 100 МБ → 413; sizeBytes заполняется;
- админка: список с занятым местом, смена роли действует со следующего
  запроса (без перелогина), удаление юзера стирает файлы с диска;
  self-demote/self-delete → 403; доступ юзером → 403;
- гость: API → 401.

UI-верификация (headless Chrome): гость видит welcome и не видит контента;
юзер не видит кнопку рендера, видит подсказку и квоты в кабинете; админ видит
админку и меняет роль.

## Вне скоупа (осознанно)

- Инвайты, email-подтверждение, восстановление пароля.
- Таблицы Role/Permission в БД, редактор ролей.
- Просмотр чужих турниров админом.
- Очередь рендера «по одобрению».
