# Спецификация 06 — Видео-проекты: пикер-режим и ручной топ

Статус: согласовано с владельцем продукта (2026-07-11), реализуется в фазе 6.

## Цель

Сайт становится генератором видео, турнир — одна из опций. Два самостоятельных
режима создания видео (сущность **VideoProject**, страница «Мои видео»):

1. **Ручной топ** (`kind: "top"`) — тот же формат видео-«топа», но позиции
   пользователь составляет сам, без турнира.
2. **Пикер** (`kind: "picker"`) — «выбери персонажа / OST / опенинг»: сверху
   правило, снизу 2–9 плиток, появляющихся по одной с анимацией, в конце
   раскрытие всех + интерактивный таймер.

Турнирный флоу не меняется (он остаётся путём «собрать топ через сравнения»).

## Согласованные решения

| Вопрос                     | Решение                                                        |
|----------------------------|----------------------------------------------------------------|
| Структура пикера           | Видео = последовательность раундов; дефолты проекта + переопределения на раунде |
| Звук                       | Видео-плитка играет свой звук во время показа, фон приглушается; картинки — под фоновую музыку раунда |
| «Правильный ответ»         | Опциональная пометка плитки; после таймера — подсветка ответа  |
| Ручной топ: аудио          | Пул медиа расширяется типом «аудио»; позиция = аудио/видео из пула |
| Сущности                   | Новая VideoProject; турниры как есть                           |
| Таймер                     | Цифры + кольцевой прогресс; тик-звук опционально (генерируем ffmpeg-ом) |
| Финал раунда               | Все плитки статично (видео — постер-кадр), звук — фон/тик      |
| Подписи плиток             | Опционально; режим показа: всегда / только на финале / никогда |

## Данные (Prisma)

- `Art.kind` получает третье значение `"audio"` (mp3/m4a/aac/flac/wav/ogg/opus);
  `durationSec`/`hasAudio` заполняются пробой, `posterPath` = null.
- `VideoProject { id, userId, title, kind: "top"|"picker", createdAt, updatedAt }`
  - пикер-дефолты: `revealSec (4)`, `hideAfterReveal (false)`, `timerSec (5)`,
    `tickSound (true)`, `bgArtId?` (картинка/видео фона), `bgMusicArtId?` (аудио).
- `PickerRound { id, projectId, order, prompt?, showPrompt (true),
  labelsMode "always"|"finale"|"never" (finale), revealSec?, hideAfterReveal?,
  timerSec?, bgArtId?, bgMusicArtId? }` — null-поля наследуют дефолты проекта.
- `PickerTile { id, roundId, order, artId (image|video), label?, isAnswer,
  playSound (true), startSec?, crop (4 поля как в RenderItem) }`
- `RenderConfig.tournamentId` → optional; + `projectId?` (unique). Ровно один
  владелец (валидация в сервисе).
- `RenderItem.trackId` → optional; + `audioArtId?` (аудио- или звуковое
  видео из пула — источник звука позиции ручного топа). Ровно один из
  trackId/audioArtId у позиции topа.
- `RenderJob.tournamentId` → optional; + `projectId?`.

## Пикер: структура раунда (тайминги)

```
[интро правила 1.5с (если showPrompt)] →
[плитка 1 … плитка N: по revealSec на каждую, анимация pop+fade;
 hideAfterReveal — плитка скрывается после своего окна] →
[финал: все плитки статично раскрыты (видео — постер), таймер timerSec
 с кольцом и цифрами, тик-звук если tickSound] →
[подсветка ответа 2с — только если есть плитка isAnswer] →
[гэп 0.7с] → следующий раунд
```

- Раскладки плиток (16:9, кроп как в топе), центрированные ряды:
  2 → 1×2; 3 → 1×3; 4 → 2×2; 5 → 3+2; 6 → 3+3; 7 → 4+3; 8 → 4+4; 9 → 3×3.
  Чистая функция `pickerLayout(n)` возвращает нормированные rect-ы.
- Подписи по labelsMode; на финале у ответа — подпись всегда (если задана).

### Звук

- Фоновая музыка раунда (`bgMusicArtId`, аудио из пула): лупится на длину
  раунда, громкость 1, **дакинг до 0.2** на окнах показа звучащих плиток.
- Видео-плитка с `playSound && hasAudio`: играет свой звук в своём окне
  (фрагмент с `startSec`, обрезка по `revealSec`, короче — луп визуала,
  звук не лупится).
- Таймер: фон + тик (короткий синус-«тик» раз в секунду, генерируется
  ffmpeg-ом в `storage/assets/tick.wav`, отдаётся через `/api/assets/tick`).
- Финал/ответ: только фон (плитки статичны).

## Ручной топ

- Тот же конструктор рендера (RenderConstructor) поверх project-конфига:
  `GET/…/api/projects/[id]/render/config` возвращает ту же форму, что
  турнирный роут.
- Позиции: добавить из пула (аудио или видео со звуком — источник звука),
  удалить, перетащить порядок (rank пересчитывается), customLabel.
- Вся механика позиции из фаз 2–4 работает: визуал из пула/своего видеоряда,
  кроп, фрагмент (manual/active_snippet/full), подмена звука, луп, сдвиг.
- Валидации: минимум 1 позиция для рендера; audioArt должен иметь звук.

## Конструктор пикера (`/projects/[id]`)

- Панель проекта: название, дефолты (revealSec, timerSec, hideAfterReveal,
  tickSound), фон (картинка/видео из пула через существующий пикер медиа),
  фоновая музыка (аудио из пула).
- Раунды: список с добавлением/удалением/перестановкой; на раунде — правило +
  «показывать правило», labelsMode, переопределения дефолтов, свой фон/музыка.
- Плитки раунда (2–9): добавить из пула (существующая модалка, фильтр
  картинки+видео), подпись, «ответ» (радио на раунд — максимум одна),
  «звук плитки» (только для видео со звуком), сдвиг старта, кроп (общий
  CropStep), перестановка.
- Живое превью всего видео (Remotion Player, план с сервера) + прогноз
  длительности; предупреждение, если раунд неполный (<2 плиток).
- Рендер: кнопка как в топе (пермишен `render:run`), прогресс, скачивание.

## Рендер-пайплайн пикера

План `PickerPlan` — единый для Player и headless-рендера (как VideoPlan):
абсолютные тайминги всех событий, ссылки на медиа. Пре-обработка при рендере:
клипы звучащих плиток (с аудио), беззвучные клипы видео-фона, постеры для
финала уже есть у видео из пула.

## Роли (фаза 5 действует)

- Проекты создают все авторизованные; рендер — только `render:run`.
- Пул медиа: аудио-файлы считаются в ту же квоту 100 МБ.
- Кабинет: проекты показываются рядом с турнирами-архивами (рендеры проектов —
  в списке рендеров), удаление проекта чистит его джобы с диска.

## Тесты

- Юнит: `pickerLayout` (2–9: количество, центрирование неполного ряда,
  непересечение, границы), `buildPickerPlan` (тайминги раундов и плиток,
  наследование дефолтов, hideAfterReveal, дакинг-окна, ответная фаза только
  при isAnswer, подписи по labelsMode, пустые/неполные раунды),
  upload: AUDIO_EXT.
- Интеграционные: CRUD проекта/раундов/плиток с изоляцией чужих данных,
  лимиты (2–9 плиток, одна isAnswer, playSound только у звучащего видео),
  аудио в пул (проба, квота), ручной топ (создание позиций из пула, ровно
  один источник звука, план), превью-план пикера (структура, наследование),
  удаление арта освобождает плитки/фон/музыку, удаление проекта чистит джобы.
- Вживую: HTTP E2E + UI-прогон конструктора + headless-рендер пикер-MP4
  с проверкой кадров (раскладка 5 = 3+2, таймер, подсветка ответа).

## Вне скоупа (осознанно)

- Переезд турнирного рендера в проекты; TTS; переходы-шаблоны между раундами;
  экспорт/импорт проектов; совместное редактирование.
